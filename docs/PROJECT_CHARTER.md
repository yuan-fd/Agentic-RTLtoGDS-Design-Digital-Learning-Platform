# OpenROAD 自演化平台项目章程

status: accepted
approved_by: user
approved_at: 2026-08-04

## 使命

在固定、可追溯的 OpenROAD/ORFS 与 PDK 基线上，建设一个面向接口、插件化、可恢复、可复现的 EDA 实验与智能优化平台。平台逐步支持自然语言任务、RTL 生成与验证、2D/3D RTL→GDSII、Flow 优化、Agent/BO 实验、证据知识积累和受控白盒演化。

## 核心原则

1. 架构草图定义产品和 Agent 协作蓝图；外部项目真实源码定义各插件内部行为。
2. Flow Agent/AgenticPD 负责智能意义上的实验规划和调度；Workflow Runtime 是进程、资源和持久状态的唯一权威。
3. 任何成功结论必须有真实命令、退出码、原始产物、哈希、指标来源和数据库状态。
4. LLM 文本、mock、dry-run、命令生成和派生可视化不构成真实 EDA 成功。
5. 外部插件使用独立环境和版本化协议；核心不 import 插件私有依赖。
6. 数据库保存关系、状态和摘要，大文件进入 Artifact Store。
7. 重试创建新 ExecutionAttempt，禁止覆盖失败证据。
8. 共享工具链和原始证据只读；自演化候选在隔离 worktree/环境验证。

## 核心实验优先原则

1. 任务首先必须实现真实最小闭环：真实上游代码 -> 真实候选生成 -> 真实参数映射 -> 真实 ORFS 执行 -> 真实日志和 QoR。
2. 未完成真实最小闭环前，不得把统计分析、p 值、多随机种子、治理文档、campaign 管理或报告美化作为主要进展。
3. 论文定义的算法参数空间必须完整保留。任何参数不得因为适配器暂时不支持而静默冻结、删除、忽略或替换。
4. 如果某个参数尚未能映射到真实 ORFS 输入，任务必须报告为“未完成”，并记录参数名称、论文含义、目标文件、阻塞原因和待办工作；不得宣称完整复现。
5. 上游算法必须使用锁定版本的真实代码。本地等价实现、简化实现或功能相似实现不能冒充上游算法。
6. 每个候选必须保留原始候选参数、映射后的 ORFS 配置、实际执行命令、运行日志、退出状态和 QoR。
7. 验收不能只看文件是否生成。必须证明不同候选实际产生不同的 ORFS 输入，并分别完成或明确失败。
8. 如果环境阻塞真实运行，必须报告阻塞，不得通过冻结核心参数、替换算法或伪造结果让流程看起来成功。
9. 所有工作按以下顺序进行：核心算法接入 -> 参数完整映射 -> 单候选真实运行 -> 多候选运行 -> 论文实验复现 -> 统计分析和报告。
10. 未经批准不得缩减核心实验范围。任何删除、冻结、替换论文参数、算法步骤、评价指标或执行阶段的行为，都必须先向用户报告影响并获得明确批准；不得以 MVP、临时适配、环境限制或先跑通为理由自行缩减。
11. 参数传递不等于参数生效。参数只有在最终 ORFS 配置、约束文件、Tcl 脚本、实际命令或工具日志中有可验证证据，并且确实影响执行，才可标记为“已接入”；只存在于 JSON、TaskSpec 或环境变量中的参数只能标记为“已传递”。
12. 进展报告必须基于证据分级。每项工作必须标明属于静态审计、代码修改、命令生成、任务启动、真实运行完成、QoR 已获得或失败阻塞；不得用“已接入”“已完成”“可用”描述尚未获得真实运行证据的工作。

## 外部研究项目接入原则

1. 外部研究项目接入的首要验收是真实可运行闭环：锁定上游代码 -> 上游算法生成完整候选 -> 全量参数进入真实工具 -> 成功或失败被 Runtime 记录 -> 结果可反馈给上游下一轮。
2. 必须区分并保留上游算法核心（候选生成、参数空间、GP/EI、反馈逻辑）与平台替换边界（SSH、路径、workspace、进程、日志、超时、取消与恢复）。平台不得以适配便利为由重写、删减或替代上游算法核心。
3. 基础 flow baseline 与上游 candidate 运行是不同验收项。baseline 证明当前工具链、PDK 与 flow 可运行；candidate 证明上游算法及全量参数接入可运行。不得用 candidate 路径掩盖 baseline 配置缺失，也不得把 baseline 默认值注入 candidate 以缩减搜索空间。
4. EDA 接入的环境合同包括工具、flow、PDK、设计、SDC、Make/Tcl 参数、动态库与操作系统，不限于 Python 依赖。每次运行必须保存可识别的环境清单、命令、最终配置、日志和终态。
5. 每次失败必须分类为 Runtime、Flow/Tcl 兼容、candidate 不可行或设计/PDK/工具链组合问题。baseline 未完成前，不得将 candidate 失败归因于 candidate 不可行。
6. 兼容修复仅可作用于 Runtime 私有副本，且必须是最小接口兼容修复；不得修改上游锁定源码、删减参数、跳过执行阶段或伪造 QoR。

## 首期范围

- 通用契约、Plugin Registry、Workflow Runtime 和可恢复状态模型。
- 现有 OpenROAD/ORFS 执行能力迁移和真实 2D 闭环。
- RTLScout、AgenticPD、TaiWei-Pin-3D 三个平台适配。
- Campaign/批量探索、有限并发、查询 API 和基础 Web。
- 自然语言生成受校验 TaskSpec，白名单式有限 ReAct。
- 带版本和证据的知识复用。

## 非目标

- 首期不上 Kubernetes、分布式微服务或多租户生产部署。
- 不重写 RTLScout、AgenticPD 或 TaiWei 的内部算法。
- 不让 Agent 绕过 Runtime 直接改最终状态或执行任意 shell。
- 不在没有基线、预算和对照实验时声称算法提升。
- 不在许可证不明确时复制或分发第三方源码。
- 不在 P1 提前实现 RAG、Coding Agent、Evolve Agent 或华丽 Web。

## 成功定义

每个阶段必须同时满足范围合规、自动化测试、必要真实验证、证据完整、文档一致、diff 审查和限制记录。阶段状态只能是完成、部分完成或阻塞，不使用“理论可用”替代证据。
