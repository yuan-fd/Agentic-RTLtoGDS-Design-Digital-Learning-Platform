# LLM Teaching Platform：本轮实施规划

## 目标

把现有 OpenROAD 平台整理成一个新人能看懂、能提问、能亲手完成设计的教学平台。本轮只做用户体验和学习闭环，不处理教师后台、评分、公开发布和运营管理。

## 用户看到的三条路

| 入口 | 适合谁 | 本轮交付 |
| --- | --- | --- |
| Labs | 想快速看到结果的人 | 可运行的 RTL、验证、DSE、RTL-to-GDS、自演化实验展示 |
| EDA Console | 想自己探索的人 | 自然语言问状态、参数、日志和报告；生成计划后受控执行 |
| Learn with Ibex | 第一次接触 OpenROAD 的人 | 逐步命令教学、GUI/日志/报告解释、一次参数比较实验 |

三个入口共享设计登记、运行任务、实时状态和证据接口，不建立第二套执行引擎。

## 实施顺序

### Phase 1：入口和课程骨架

#### Task 1：三个入口的页面结构

**验收标准**

- [x] 首页能直接进入 Labs、EDA Console、Learn with Ibex。
- [x] 每个入口有一句说明，用户不看文档也能理解用途。
- [x] 原有 Frontend、Backend、Projects、Self-evolution 入口继续可用。

**验证**：网页回归测试；桌面和窄屏手工浏览。

**依赖**：无。  
**范围**：Small，`apps/web/index.html`、`apps/web/assets/app.css`。

#### Task 2：Ibex 四步课程

**验收标准**

- [x] 课程包含认识设计、baseline、结果阅读、参数比较四步。
- [x] 每步同时显示命令、命令解释、观察重点和下一步。
- [x] 用户可以自己尝试、查看答案、切换步骤。

**验证**：浏览器手工完成四步；网页脚本语法检查。

**依赖**：Task 1。  
**范围**：Medium，`apps/web/index.html`、`apps/web/assets/app.js`、`apps/web/assets/app.css`。

### Checkpoint 1：课程可浏览

- [ ] 三个入口清楚可见。
- [ ] Ibex 课程四步可切换。
- [ ] 现有网页测试全部通过。

### Phase 2：控制台的真实帮助

#### Task 3：状态和阶段问答

**验收标准**

- [x] 助手能读取当前设计和运行状态。
- [x] “我现在到哪一步”返回真实阶段和下一步。
- [x] 没有运行时明确告诉用户先选择设计或启动任务。

**验证**：使用一个真实 Ibex 任务，分别在排队、运行、完成、失败状态提问。

**依赖**：Task 1；现有 Runtime API。  
**范围**：Medium，复用现有 `Teaching Session` 和 Dashboard 接口。

#### Task 4：报告和失败解释

**验收标准**

- [x] 助手能解释面积、时序、拥塞、DRC 等常见字段。
- [x] 失败回答使用“原因、影响、建议”三段式。
- [x] 回答引用真实报告或运行证据，不编造数字。

**验证**：准备一个成功报告和一个失败任务，检查回答中的证据指针。

**依赖**：Task 3。  
**范围**：Medium，复用报告解析和 evidence view。

### Checkpoint 2：控制台可问可查

- [ ] 新人可以询问当前状态。
- [ ] 新人可以询问报告字段。
- [ ] 失败任务能得到可执行的下一步建议。
- [ ] 所有建议仍经过受控执行边界。

### Phase 3：自由探索闭环

#### Task 5：自然语言生成实验计划

**验收标准**

- [ ] 用户可以描述比较目标，例如“比较 40%、50%、60% 利用率”。
- [ ] 平台展示参数差异、候选数量和预计步骤。
- [ ] 默认候选数为 3，上限为 6。
- [ ] 用户确认前不启动实验。

**验证**：生成一次 Rule Batch 计划，确认候选参数和现有 DSE API 一致。

**依赖**：Task 3、Task 4、现有 DSE batch API。  
**范围**：Medium。

#### Task 6：教学模式的命令练习

**验收标准**

- [ ] 用户可以在课程中输入命令。
- [ ] 平台能判断命令属于当前步骤、是否缺少关键参数。
- [ ] 判断失败时给出修改建议，不直接替用户执行任意命令。
- [ ] 正确后可以把命令转换成受控任务请求。

**验证**：覆盖正确命令、缺参数命令、跨步骤命令和明显危险命令。

**依赖**：Task 2、Task 3。  
**范围**：Medium，优先使用白名单和结构化解析，不引入 Shell 解释器。

### Checkpoint 3：第一次完整学习闭环

- [ ] 新人使用 Ibex 完成一次真实 baseline。
- [ ] 能在页面看到阶段状态、GUI、日志和报告。
- [ ] 修改一个参数后完成第二次运行并看到差异。
- [ ] 运行证据可回到 Projects 和 Self-evolution 页面查看。

## 统一交互规则

1. 页面先显示“现在是什么状态”，再显示“可以做什么”。
2. 执行前显示计划、参数和影响范围。
3. 执行中显示阶段、进度、耗时和失败位置。
4. 执行后显示真实指标、证据和下一步实验建议。
5. 预测值、历史值、快速代理值和真实 OpenROAD 结果必须分开标记。
6. 默认简洁显示，高级参数通过“查看详情”展开。

## 暂不做

- 教师后台和课程评分；
- 用户自带服务器或自定义模型；
- 任意 Shell 命令执行；
- 未经证据验证的知识自动入库；
- 为了“看起来完整”而新增独立服务或前端框架。

## 完成定义

本轮规划完成后，用户可以从首页选择三条路径中的任意一条；可以用 Ibex 课程走完一次设计；可以用自然语言询问真实状态和报告；可以在确认后生成并运行一次受控参数比较实验；所有结果都能在 Dashboard 和项目记录中复查。
