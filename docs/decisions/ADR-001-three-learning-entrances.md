# ADR-001：教学平台的三个学习入口

## 状态

Accepted · 2026-09-12

## 背景

OpenROAD 对新人最难的地方不是缺少工具，而是工具、参数、日志和结果之间没有一条容易理解的学习路径。平台既要展示已经准备好的实验，也要允许用户提出自己的问题，还要手把手教会新人完成一次真实设计。

## 决策

平台使用三个并列入口，三者共享同一套设计记录、运行任务、实时状态和证据：

1. **Labs 展示区**：提供可重复运行的完整实验。第一批包括 RTL 生成与 RTLScout 对比、RTL 验证、参数空间探索、RTL-to-GDS 和证据学习。
2. **自然语言 EDA 控制台**：用户用自然语言询问状态、报告、参数和失败原因。助手先给出理解、计划、命令和参数，用户确认后才进入受控执行。
3. **师傅式教学模式**：以 Ibex 为第一条完整课程，逐步教用户看目录、读 RTL、写约束、运行流程、查看 GUI、日志、报告和 QoR，再修改一个参数并比较结果。

三个入口不各自实现执行逻辑。它们都调用现有的 ExperimentService、Teaching Session、Runtime 和证据接口；差别只在于用户看到的引导方式。

## 第一条 Ibex 课程

课程按一个概念一个步骤组织：

1. 认识设计目录和顶层模块；
2. 查看 RTL、时钟和基本约束；
3. 运行综合并理解面积、门数和时序；
4. 运行 floorplan、布局、CTS 和布线；
5. 在 GUI、日志和报告中定位关键结果；
6. 修改利用率或时钟约束，重新运行并比较两次真实证据。

每一步都显示：目标、命令、命令中每个关键部分的含义、应该观察的结果，以及继续或返回的操作。

## 约束

- 自然语言不能直接变成任意 Shell 命令；必须先形成可审查的计划。
- 教学模式默认隐藏复杂参数，但每一步都提供“查看可调参数”的入口。
- Labs 必须保留真实运行和证据边界，不能用 replay 冒充新实验。
- 三个入口保持简洁、明亮、清楚的网页风格；不使用渐变背景、模糊底板或无法解释的装饰性卡片。

## 后果

- 新人可以从 Lab 直接看到结果，也可以从课程从零开始。
- 熟悉 OpenROAD 的用户可以跳过课程，直接使用自然语言控制台探索。
- 运行、日志、报告和证据只维护一套，减少旧 API 和重复状态造成的混乱。
- 第一版课程先只承诺 Ibex；增加其他设计需要复用同一课程步骤契约。

## 未纳入本阶段

教师后台、课程评分、公开发布和多租户运营管理继续留到功能成熟后处理。
